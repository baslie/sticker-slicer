# sticker-slicer

Скрипты для подготовки наборов die-cut стикеров: экспорт из Adobe Illustrator
в отдельные PNG-файлы с прозрачным фоном и белой контурной подложкой, плюс
диагностический дамп структуры `.ai`-документа.

## Структура репозитория

```
sticker-slicer/
├── README.md
├── .gitignore
├── scripts/
│   ├── StickerExporter.jsx     — экспортёр стикеров (ExtendScript)
│   └── DiagnoseDocument.jsx    — дамп структуры .ai в текстовый отчёт
└── sources/
    ├── NAKL_LOVE_180.ai        — макет «LOVE» (180 мм)
    └── NAKL_COLOR_260.ai       — макет «COLOR» (260 мм)
```

Скрипты работают с любым `.ai`-документом — не только с тем, что лежит рядом
в `sources/`. Папка `sources/` — просто оригиналы текущих наборов.

## `scripts/StickerExporter.jsx`

ExtendScript для Adobe Illustrator. Берёт макет с раскладкой стикеров на
одном artboard и сохраняет **каждый стикер в отдельный PNG с прозрачным фоном**
и белой контурной подложкой. Дополнительно пишет `sizes.json` с физическими
размерами каждого стикера.

### Что делает по шагам

1. **Собирает все stroked-пути** на видимых, незаблокированных слоях
   документа (включая обходы внутри `groupItems` и `compoundPathItems`).
2. **Группирует обводки** по двум признакам:
   - spot-цвет (`SpotColor`) — каждое уникальное имя спот-цвета это отдельная
     группа;
   - сплошные CMYK/RGB обводки — группируются по округлённым значениям каналов.
3. **Показывает диалог**, где пользователь:
   - выбирает, какая группа обводок является контуром реза (cut-line);
   - корректирует параметры экспорта (см. ниже);
   - указывает имена слоёв, которые **не нужно** учитывать при поиске
     cut-контуров и при сборе картинок (по умолчанию `MARKS CUT`);
   - указывает выходную папку.
4. Для каждого cut-контура (`cutItem`) выполняется **изолированный экспорт**:
   1. Создаётся временный слой `__TEMP_STICKER_EXPORT__` поверх остальных.
   2. В него **дублируются объекты с других слоёв**, чьи `geometricBounds`
      пересекаются с bbox cut-контура (другие cut-линии при этом
      отфильтровываются — чтобы соседние стикеры не попали в кадр).
   3. Дублируется сам cut-контур как **белая подложка**: заливка белая,
      обводка белая толщиной `whiteOutlinePt × 2`, `strokeJoin = ROUNDENDJOIN`,
      отправляется в самый низ слоя (`SENDTOBACK`).
   4. Дублируется ещё одна копия cut-контура как **clipping mask** наверху
      (без заливки и обводки).
   5. Через `app.executeMenuCommand("makeMask")` применяется маска ко всему
      содержимому временного слоя.
   6. **Все остальные слои скрываются** на время экспорта.
   7. Создаётся временный artboard размером bbox + `paddingPt`.
   8. PNG24 экспортируется с настройками:
      `transparency = true`, `matte = false`, `artBoardClipping = true`,
      `antiAliasing = true`, масштаб `horizontalScale = verticalScale = exportScalePercent`.
   9. В `finally`: удаляется временный artboard, восстанавливается активный
      artboard, удаляется временный слой со всем содержимым, возвращается
      исходная видимость всех слоёв (она сохранялась до начала цикла
      в `origLayerVisibility`).
5. После цикла записывается `sizes.json` (см. ниже).
6. По завершении выводится итоговое окно: сколько стикеров экспортировано,
   путь к `sizes.json` и список первых пяти ошибок (если были).

### `sizes.json` — что внутри

Файл сохраняется рядом с PNG в выбранной выходной папке. Формат:

```json
{
  "document": "NAKL_COLOR_260.ai",
  "exported_at": "2026-05-28T14:32:10",
  "settings": {
    "white_outline_mm": 2.5,
    "padding_mm": 1.0,
    "export_scale_percent": 200
  },
  "stickers": [
    {
      "file": "sticker_001.png",
      "cut_size_mm":           { "width": 48.2, "height": 53.7 },
      "with_white_outline_mm": { "width": 53.2, "height": 58.7 },
      "png_size_mm":           { "width": 55.2, "height": 60.7 }
    }
  ]
}
```

- `cut_size_mm` — bbox самого cut-контура.
- `with_white_outline_mm` — bbox + белая подложка по периметру
  (`+ 2 × white_outline_mm`).
- `png_size_mm` — фактический размер PNG в мм
  (`+ 2 × (white_outline_mm + padding_mm)`).

ExtendScript не имеет нативного `JSON.stringify` и `Date.prototype.toISOString` —
оба заменены ручными реализациями (`toJSON`, `nowISO`).

### Параметры (диалог + блок `SETTINGS`)

| Параметр              | Дефолт                       | Назначение |
|-----------------------|------------------------------|------------|
| `whiteOutlineMm`      | `2.5` мм                     | Толщина белой подложки вокруг стикера. В коде применяется как `strokeWidth = whiteOutlinePt × 2` — обводка идёт по центру контура, поэтому наружу выступает ровно `whiteOutlineMm`. |
| `paddingMm`           | `1.0` мм                     | Запас на artboard сверх белой подложки. Реальный паддинг artboard = `paddingMm × MM2PT + whiteOutlinePt`. |
| `exportScalePercent`  | `200` %                      | Масштаб итогового PNG относительно макета. |
| `fileNamePrefix`      | `"sticker_"`                 | Префикс имён файлов. Итог: `sticker_001.png`, `sticker_002.png`, … (нумерация с дополнением нулями до 3 знаков). |
| `sizesFileName`       | `"sizes.json"`               | Имя файла отчёта с размерами. |
| Исключить слои        | `MARKS CUT`                  | Имена слоёв через запятую — пропускаются и при поиске cut-контуров, и при сборе пересекающихся объектов. Удобно для слоя с типографскими метками реза, которые сами по форме совпадают с cut-цветом. |
| `TEMP_LAYER_NAME`     | `"__TEMP_STICKER_EXPORT__"`  | Имя временного слоя; меняется только если в макете уже есть слой с таким именем. |

`MM2PT = 2.83464567` — пересчёт миллиметров в пункты Illustrator.

### Что решает эта реализация (vs. наивный экспорт по artboard'ам)

- Соседние стикеры **не попадают в кадр** — кадрирование идёт через clipping
  mask по форме cut-контура, а не только через artboard.
- Любой посторонний фон/подложка из других слоёв (включая чёрный фон под
  `PRINT`, если он есть) **исключается** — все слои кроме временного скрыты.
- Сама cut-линия **не остаётся** в финальном PNG — она используется только
  как форма подложки и маски.
- Слой `MARKS CUT` с типографскими метками реза, который рисуется тем же
  цветом, что и cut-контур, можно исключить и не получить лишних
  «стикеров-меток».

### Установка и запуск

1. Открыть `.ai`-файл (например, `sources/NAKL_COLOR_260.ai`) в Adobe Illustrator.
2. `File → Scripts → Other Script…` → выбрать `scripts/StickerExporter.jsx`.
3. В диалоге:
   - выбрать, какие линии — контуры реза;
   - при необходимости поправить параметры;
   - проверить список исключаемых слоёв;
   - нажать **Экспортировать**.
4. Выбрать папку, куда сохранить PNG и `sizes.json`.

## `scripts/DiagnoseDocument.jsx`

Диагностический дамп структуры активного `.ai`-документа. Нужен, когда
приходит новый макет и непонятно, как настроить экспортёр.

### Что собирает

- Имя документа, путь, color space.
- Список artboards с размерами в мм.
- Полную иерархию слоёв с флагами `hidden` / `locked` и счётчиками объектов
  каждого типа.
- Сводную статистику по всему документу (PathItems, CompoundPathItems,
  GroupItems, TextFrames, PlacedItems, RasterItems, SymbolItems, MeshItems).
- Группировку всех stroked-путей по цвету обводки (spot / CMYK / RGB)
  с примером bounding box и толщины обводки — чтобы понять, какой цвет
  выбирать как cut-line в `StickerExporter`.
- Список spot colors документа.

### Куда сохраняется отчёт

`<имя_документа>__report.txt` рядом с самим `.ai`-файлом. Если документ ещё
не сохранён — на Desktop.

### Запуск

1. Открыть `.ai`-файл в Adobe Illustrator.
2. `File → Scripts → Other Script…` → выбрать `scripts/DiagnoseDocument.jsx`.
3. По завершении скрипт покажет путь к сохранённому отчёту.

## `scripts/PreflightBatch.jsx`

Пакетная проверка целой папки `.ai`-макетов **перед** запуском
`StickerExporter`. В отличие от `DiagnoseDocument` (один файл, человекочитаемый
дамп) — открывает все файлы папки по очереди, проверяет их против фактического
контракта экспортёра и выдаёт по каждому явный вердикт **PASS / WARN / FAIL**.

### Зачем

`StickerExporter` молча выдаёт брак или 0 контуров, если макет не отвечает его
ожиданиям. Preflight ловит это заранее — особенно полезно, когда приходит пачка
новых макетов от разных дизайнеров.

### Что проверяет (контракт экспортёра)

1. Есть ли stroked-пути на видимых незаблокированных слоях верхнего уровня —
   только их видит экспортёр.
2. Какие есть группы обводок и какая — кандидат на контур реза (эвристика:
   spot-цвет в приоритете, иначе самая многочисленная группа).
3. Сколько контуров реза найдено и бьётся ли это с числом, зашитым в имени
   файла (`BMW_110` → 110) — **мягкая** подсказка, не вердикт.
4. Не лежит ли рез на скрытом/заблокированном слое (тогда экспортёр найдёт 0).
5. **Блайндспот экспортёра:** обводки в *подслоях* (`layer.layers`).
   `collectAllStroked` не заходит в подслои — если рез там, он будет пропущен.
   Preflight считает такие пути отдельно и предупреждает.
6. Неоднозначность cut-цвета: несколько сопоставимых stroke-групп = вероятный
   «развал» одного реза на разные значения цвета.
7. Подозрение на фон во весь лист (объект с bbox ≈ artboard) на не-cut слое —
   он попадёт фоном под каждый стикер.
8. Есть ли вообще картинки (raster/placed) — иначе стикеры выйдут пустыми.
9. Замкнуты ли контуры-кандидаты (открытые плохо работают как clipping mask).

### Куда сохраняется отчёт

В выбранную папку: `preflight.json` (машиночитаемый — удобно переслать в чат
для разбора) и `preflight.txt` (человекочитаемая сводка с группами обводок по
каждому файлу).

### Запуск

1. `File → Scripts → Other Script…` → выбрать `scripts/PreflightBatch.jsx`.
2. В диалоге выбрать папку с макетами (например, `Desktop/Макеты`).
3. По завершении скрипт покажет сводку `PASS/WARN/FAIL` и пути к отчётам.

> Открытие диалогов (нехватка шрифтов, цветовые профили) подавляется на время
> прогона (`UserInteractionLevel.DONTDISPLAYALERTS`). Файлы открываются и
> закрываются **без сохранения** — оригиналы не меняются.

## Технологии

- Adobe Illustrator + ExtendScript (`.jsx`, диалект ES3).
- Никаких внешних зависимостей и сборки — скрипты запускаются напрямую
  через `File → Scripts → Other Script…`.
