# sticker-slicer

Скрипты для подготовки наборов die-cut стикеров: экспорт из Adobe Illustrator
в отдельные PNG-файлы с прозрачным фоном и белой контурной подложкой,
плюс PNG всего листа целиком, плюс диагностический дамп структуры
`.ai`-документа.

## Структура репозитория

```
sticker-slicer/
├── README.md
├── .gitignore
├── scripts/                       — операционный набор (проверить → выгрузить)
│   ├── StickerCore.jsx            — общий движок экспорта (без UI), подключается рядом
│   ├── StickerExporter.jsx        — экспортёр одного открытого документа (диалог)
│   ├── BatchExporter.jsx          — пакетный экспорт всех .ai из папки
│   ├── PreflightBatch.jsx         — пакетная проверка макетов (PASS/WARN/FAIL)
│   ├── fixes/                     — починка макетов перед экспортом (по необходимости)
│   │   ├── FixClipCut.jsx         — навесить рез на невидимый clip-путь
│   │   └── CloseOpenCutPaths.jsx  — замкнуть открытые контуры реза
│   └── diagnostics/              — read-only разбор странных файлов (редко)
│       ├── DiagnoseDocument.jsx   — дамп структуры .ai в текстовый отчёт
│       ├── InspectCutCandidates.jsx — поиск «спрятанного» контура реза
│       └── InspectCutGeometry.jsx — геометрия контуров реза + перекрытия
└── sources/
    ├── NAKL_LOVE_180.ai          — макет «LOVE» (180 мм)
    └── NAKL_COLOR_260.ai         — макет «COLOR» (260 мм)
```

Скрипты работают с любым `.ai`-документом — не только с тем, что лежит рядом
в `sources/`. Папка `sources/` — просто оригиналы текущих наборов.

**Зависимости.** `StickerCore.jsx` — общий движок (группировка обводок, авто-выбор
реза, экспорт одного документа). Его подключают через `$.evalFile` и
`StickerExporter.jsx`, и `BatchExporter.jsx` — логика экспорта одна на оба, поэтому
фиксы не расходятся. Эти три файла должны лежать в **одной папке** `scripts/`. Скрипты
в `fixes/` и `diagnostics/` самостоятельные (ничего не подключают) — их расположение
не важно, они вынесены в подпапки просто для порядка.

## `scripts/StickerExporter.jsx`

ExtendScript для Adobe Illustrator. Берёт макет с раскладкой стикеров на
одном artboard и сохраняет **каждый стикер в отдельный PNG с прозрачным фоном**
и белой контурной подложкой, а также **весь лист целиком одним PNG**
(см. [PNG всего листа](#png-всего-листа)). Дополнительно пишет `sizes.json`
с физическими размерами каждого стикера и самого листа.

### Что делает по шагам

1. **Собирает все stroked-пути** на видимых, незаблокированных слоях
   документа (включая обходы внутри `groupItems` и `compoundPathItems`).
2. **Группирует обводки** по двум признакам:
   - spot-цвет (`SpotColor`) — каждое уникальное имя спот-цвета это отдельная
     группа;
   - сплошные CMYK/RGB обводки — группируются по округлённым значениям каналов.
3. **Показывает диалог**, где пользователь:
   - выбирает, какая группа обводок является контуром реза (cut-line);
   - корректирует параметры экспорта (см. ниже);
   - указывает имена слоёв, которые **не нужно** учитывать при поиске
     cut-контуров и при сборе картинок (по умолчанию `MARKS CUT`);
   - указывает выходную папку.
4. Для каждого cut-контура (`cutItem`) выполняется **изолированный экспорт**:
   1. Создаётся временный слой `__TEMP_STICKER_EXPORT__` поверх остальных.
   2. В него **дублируются объекты с других слоёв**, чьи `geometricBounds`
      пересекаются с bbox cut-контура (другие cut-линии при этом
      отфильтровываются — чтобы соседние стикеры не попали в кадр).
   3. Дублируется сам cut-контур как **белая подложка**: заливка белая,
      обводка белая толщиной `whiteOutlinePt × 2`, `strokeJoin = ROUNDENDJOIN`,
      отправляется в самый низ слоя (`SENDTOBACK`).
   4. Дублируется ещё одна копия cut-контура как **clipping mask** наверху
      (без заливки и обводки).
   5. Через `app.executeMenuCommand("makeMask")` применяется маска ко всему
      содержимому временного слоя.
   6. **Все остальные слои скрываются** на время экспорта.
   7. Создаётся временный artboard размером bbox + `paddingPt`.
   8. PNG24 экспортируется с настройками:
      `transparency = true`, `matte = false`, `artBoardClipping = true`,
      `antiAliasing = true`, масштаб `horizontalScale = verticalScale = exportScalePercent`.
   9. В `finally`: удаляется временный artboard, восстанавливается активный
      artboard, удаляется временный слой со всем содержимым, возвращается
      исходная видимость всех слоёв (она сохранялась до начала цикла
      в `origLayerVisibility`).
5. После цикла экспортируется **весь лист** — PNG каждого artboard документа
   (см. [PNG всего листа](#png-всего-листа)).
6. Записывается `sizes.json` (см. ниже).
7. По завершении выводится итоговое окно: сколько стикеров экспортировано,
   имя и размер листа, путь к `sizes.json` и список первых пяти ошибок
   (если были).

### PNG всего листа

Помимо отдельных стикеров скрипт выгружает **сам лист** — по одному PNG на
каждый artboard документа, тем же экспортом (PNG24, прозрачность, тот же
`exportScalePercent`, обрезка по границам artboard).

| Вариант в диалоге          | Файл            | Что внутри |
|----------------------------|-----------------|------------|
| чистовой *(по умолчанию)*  | `sheet.png`     | Лист таким, каким печатается: линии реза сняты, исключённые слои (`MARKS CUT`) скрыты. |
| как в макете               | `sheet_raw.png` | Artboard как есть — со всеми линиями реза и служебными слоями. |
| оба варианта               | `sheet.png` + `sheet_raw.png` | Оба файла сразу. |

Если в документе **больше одного artboard**, к имени добавляется номер:
`sheet_01.png`, `sheet_02.png`, … (и `sheet_raw_01.png`, …).

Размер листа попадает в `sizes.json` (секция `sheets`) и в итоговое окно:
`sheet_size_mm` — физический размер artboard, `stickers_area_mm` — габарит
всех контуров реза на этом листе (сколько места реально занимают стикеры).

Чекбокс **«Экспортировать лист целиком»** выключает эту часть, если нужны
только отдельные стикеры.

> Для чистового варианта обводки цвета реза временно снимаются **в самом
> документе** и возвращаются сразу после экспорта — запоминаются флаг
> `stroked`, цвет и толщина обводки. Документ при этом помечается как
> изменённый: сохранять его не нужно (пакетный режим и так закрывает файлы
> без сохранения). Фон листа, если он есть отдельным слоем, в чистовой
> вариант попадает — чтобы убрать, добавь имя слоя в «Исключить слои».
> Если контуры реза не найдены вовсе, лист всё равно выгружается.

### `sizes.json` — что внутри

Файл сохраняется рядом с PNG в выбранной выходной папке. Формат:

```json
{
  "document": "NAKL_COLOR_260.ai",
  "exported_at": "2026-05-28T14:32:10",
  "settings": {
    "white_outline_mm": 2.5,
    "padding_mm": 1.0,
    "export_scale_percent": 200,
    "export_sheet": true,
    "sheet_mode": "clean"
  },
  "sheets": [
    {
      "file": "sheet.png",
      "mode": "clean",
      "artboard": "Artboard 1",
      "sheet_size_mm":    { "width": 260.0, "height": 380.0 },
      "stickers_area_mm": { "width": 248.3, "height": 366.1 }
    }
  ],
  "stickers": [
    {
      "file": "sticker_001.png",
      "cut_size_mm":           { "width": 48.2, "height": 53.7 },
      "with_white_outline_mm": { "width": 53.2, "height": 58.7 },
      "png_size_mm":           { "width": 55.2, "height": 60.7 }
    }
  ]
}
```

- `sheets[].sheet_size_mm` — физический размер листа (artboard) в мм.
- `sheets[].stickers_area_mm` — габарит всех контуров реза на этом листе;
  отсутствует, если контуров нет.
- `cut_size_mm` — bbox самого cut-контура.
- `with_white_outline_mm` — bbox + белая подложка по периметру
  (`+ 2 × white_outline_mm`).
- `png_size_mm` — фактический размер PNG в мм
  (`+ 2 × (white_outline_mm + padding_mm)`).

ExtendScript не имеет нативного `JSON.stringify` и `Date.prototype.toISOString` —
оба заменены ручными реализациями (`toJSON`, `nowISO`).

### Параметры (диалог + блок `SETTINGS`)

| Параметр              | Дефолт                       | Назначение |
|-----------------------|------------------------------|------------|
| `whiteOutlineMm`      | `2.5` мм                     | Толщина белой подложки вокруг стикера. В коде применяется как `strokeWidth = whiteOutlinePt × 2` — обводка идёт по центру контура, поэтому наружу выступает ровно `whiteOutlineMm`. |
| `paddingMm`           | `1.0` мм                     | Запас на artboard сверх белой подложки. Реальный паддинг artboard = `paddingMm × MM2PT + whiteOutlinePt`. |
| `exportScalePercent`  | `200` %                      | Масштаб итогового PNG относительно макета. |
| `fileNamePrefix`      | `"sticker_"`                 | Префикс имён файлов. Итог: `sticker_001.png`, `sticker_002.png`, … (нумерация с дополнением нулями до 3 знаков). |
| `sizesFileName`       | `"sizes.json"`               | Имя файла отчёта с размерами. |
| `exportSheet`         | `true`                       | Выгружать ли PNG всего листа. В диалоге — чекбокс «Экспортировать лист целиком». |
| `sheetMode`           | `"clean"`                    | Вариант листа: `"clean"` (без линий реза), `"raw"` (как в макете), `"both"` (оба файла). В диалоге — выпадающий список. |
| `sheetFileName`       | `"sheet"`                    | База имени файла листа: `sheet.png`, `sheet_raw.png`, `sheet_01.png`. |
| Исключить слои        | `MARKS CUT`                  | Имена слоёв через запятую — пропускаются и при поиске cut-контуров, и при сборе пересекающихся объектов. Удобно для слоя с типографскими метками реза, которые сами по форме совпадают с cut-цветом. |
| `TEMP_LAYER_NAME`     | `"__TEMP_STICKER_EXPORT__"`  | Имя временного слоя; меняется только если в макете уже есть слой с таким именем. |

`MM2PT = 2.83464567` — пересчёт миллиметров в пункты Illustrator.

### Что решает эта реализация (vs. наивный экспорт по artboard'ам)

- Соседние стикеры **не попадают в кадр** — кадрирование идёт через clipping
  mask по форме cut-контура, а не только через artboard. Пересечение объектов
  с контуром меряется по **видимым** границам (`visibleBounds`), а не
  геометрическим: иначе обрезанная группа-стикер (фото больше своей клип-рамки
  и торчит в соседнюю ячейку) затягивала бы соседа в кадр.
- Любой посторонний фон/подложка из других слоёв (включая чёрный фон под
  `PRINT`, если он есть) **исключается** — все слои кроме временного скрыты.
- Сама cut-линия **не остаётся** в финальном PNG — она используется только
  как форма подложки и маски. Если линия реза спрятана *внутри* группы стикера
  (вместе с графикой), группа дублируется целиком — поэтому перед маскировкой
  у всей дублированной графики снимается обводка cut-цвета (`stripCutStrokes`),
  иначе magenta-линия проступала бы по краю стикера.
- Слой `MARKS CUT` с типографскими метками реза, который рисуется тем же
  цветом, что и cut-контур, можно исключить и не получить лишних
  «стикеров-меток».
- **Производительность на мега-группах.** Если вся графика собрана в одну
  большую группу во весь лист, наивный сбор пересечений дублировал бы всю
  графику листа на каждый контур (O(n²)). `collectIntersectingItems` разбирает
  большие *простые* группы-контейнеры (без клиппинга, прозрачности и
  blend-режима) на детей и берёт только реально пересекающие контур объекты.
  Группы с собственным оформлением (клип/opacity/blend) дублируются целиком —
  чтобы не потерять обрезку и вид.

### Установка и запуск

1. Открыть `.ai`-файл (например, `sources/NAKL_COLOR_260.ai`) в Adobe Illustrator.
2. `File → Scripts → Other Script…` → выбрать `scripts/StickerExporter.jsx`.
3. В диалоге:
   - выбрать, какие линии — контуры реза;
   - при необходимости поправить параметры;
   - проверить список исключаемых слоёв;
   - выбрать, нужен ли PNG всего листа и в каком варианте;
   - нажать **Экспортировать**.
4. Выбрать папку, куда сохранить PNG стикеров, PNG листа и `sizes.json`.

## `scripts/BatchExporter.jsx`

Пакетный экспорт: за **один запуск** обрабатывает все `.ai`-макеты из выбранной
папки. Удобно, когда макетов много и прогонять интерактивный экспортёр по одному
долго. Использует тот же движок (`StickerCore.jsx`), что и `StickerExporter`.

### Что делает по шагам

1. Просит **папку с макетами** и проверяет её: внутри должны быть **только
   `.ai`-файлы** — никаких подпапок и посторонних файлов (системный мусор
   `Thumbs.db`/`.DS_Store`/`desktop.ini` игнорируется). Если есть лишнее —
   показывает список и просит исправить папку, экспорт не начинает.
2. Один раз спрашивает параметры (белая подложка, запас, масштаб, исключаемые
   слои, лист целиком и его вариант) — они применяются ко всем файлам.
3. Просит **выходную папку** (предупреждает, если она совпадает с входной).
4. Поочерёдно открывает каждый `.ai`, **сам определяет цвет контура реза**
   (`SC_pickCutCandidate`: spot в приоритете, иначе самая массовая обводка),
   выгружает стикеры **и PNG всего листа** в **подпапку с именем файла**
   внутри выходной папки (`outRoot/<имя_без_.ai>/`), закрывает документ без
   сохранения.
5. Пишет сводный отчёт `batch_report.txt` и `batch_report.json` в выходную папку.

Работает и когда в папке **один файл** (частный случай, N=1).

### Требования к папке и поведение

- **Файлы должны быть готовы к экспорту.** Пакетник НЕ чинит макеты. Проблемные
  клади уже почивленными копиями: `*__cut.ai` (после `FixClipCut` — невидимый
  рез) и `*__closed.ai` (после `CloseOpenCutPaths` — открытые контуры). Файлы
  без найденного реза пакетник **пропускает** целиком — для них не выгружается
  и лист — и отмечает их в отчёте.
- **Подпапки перезаписываются:** перед экспортом старые `sticker_*.png` и
  `sheet*.png` в подпапке удаляются, чтобы не осталось хвостов от прошлого
  прогона.
- В отчётах появляются счётчик листов (`sheets_total`) и размер листа по
  каждому файлу.
- На время прогона подавляются диалоги Illustrator (нехватка шрифтов, цветовые
  профили). Оригиналы открываются и закрываются **без сохранения** — не меняются.

### Запуск

1. `File → Scripts → Other Script…` → выбрать `scripts/BatchExporter.jsx`.
2. Выбрать папку с макетами → параметры → выходную папку.
3. По завершении — окно с итогом и путь к `batch_report.txt`.

## `scripts/diagnostics/DiagnoseDocument.jsx`

Диагностический дамп структуры активного `.ai`-документа. Нужен, когда
приходит новый макет и непонятно, как настроить экспортёр.

### Что собирает

- Имя документа, путь, color space.
- Список artboards с размерами в мм.
- Полную иерархию слоёв с флагами `hidden` / `locked` и счётчиками объектов
  каждого типа.
- Сводную статистику по всему документу (PathItems, CompoundPathItems,
  GroupItems, TextFrames, PlacedItems, RasterItems, SymbolItems, MeshItems).
- Группировку всех stroked-путей по цвету обводки (spot / CMYK / RGB)
  с примером bounding box и толщины обводки — чтобы понять, какой цвет
  выбирать как cut-line в `StickerExporter`.
- Список spot colors документа.

### Куда сохраняется отчёт

`<имя_документа>__report.txt` рядом с самим `.ai`-файлом. Если документ ещё
не сохранён — на Desktop.

### Запуск

1. Открыть `.ai`-файл в Adobe Illustrator.
2. `File → Scripts → Other Script…` → выбрать `scripts/diagnostics/DiagnoseDocument.jsx`.
3. По завершении скрипт покажет путь к сохранённому отчёту.

## `scripts/PreflightBatch.jsx`

Пакетная проверка целой папки `.ai`-макетов **перед** запуском
`StickerExporter`. В отличие от `DiagnoseDocument` (один файл, человекочитаемый
дамп) — открывает все файлы папки по очереди, проверяет их против фактического
контракта экспортёра и выдаёт по каждому явный вердикт **PASS / WARN / FAIL**.

### Зачем

`StickerExporter` молча выдаёт брак или 0 контуров, если макет не отвечает его
ожиданиям. Preflight ловит это заранее — особенно полезно, когда приходит пачка
новых макетов от разных дизайнеров.

### Что проверяет (контракт экспортёра)

1. Есть ли stroked-пути на видимых незаблокированных слоях верхнего уровня —
   только их видит экспортёр.
2. Какие есть группы обводок и какая — кандидат на контур реза (эвристика:
   spot-цвет в приоритете, иначе самая многочисленная группа).
3. Сколько контуров реза найдено и бьётся ли это с числом, зашитым в имени
   файла (`BMW_110` → 110) — **мягкая** подсказка, не вердикт.
4. Не лежит ли рез на скрытом/заблокированном слое (тогда экспортёр найдёт 0).
5. **Блайндспот экспортёра:** обводки в *подслоях* (`layer.layers`).
   `collectAllStroked` не заходит в подслои — если рез там, он будет пропущен.
   Preflight считает такие пути отдельно и предупреждает.
6. Неоднозначность cut-цвета: несколько сопоставимых stroke-групп = вероятный
   «развал» одного реза на разные значения цвета.
7. Настоящий фон во весь лист — *залитый* объект (path/raster/placed) с
   bbox ≈ artboard. Группы-контейнеры (в которые просто сложены все стикеры)
   при этом НЕ считаются фоном.
8. Мега-группа: вся графика собрана в одну-две группы во весь лист при большом
   числе контуров — экспортёр будет дублировать всю графику на каждый стикер
   (O(n²), очень медленно). Лучше разгруппировать по стикерам.
9. Есть ли вообще графика для вклейки (группы/картинки) на видимых слоях —
   считается векторный арт, а не только raster/placed.
10. Замкнуты ли контуры-кандидаты (открытые плохо работают как clipping mask).

### Куда сохраняется отчёт

В выбранную папку: `preflight.json` (машиночитаемый — удобно переслать в чат
для разбора) и `preflight.txt` (человекочитаемая сводка с группами обводок по
каждому файлу).

### Запуск

1. `File → Scripts → Other Script…` → выбрать `scripts/PreflightBatch.jsx`.
2. В диалоге выбрать папку с макетами (например, `Desktop/Макеты`).
3. По завершении скрипт покажет сводку `PASS/WARN/FAIL` и пути к отчётам.

> Открытие диалогов (нехватка шрифтов, цветовые профили) подавляется на время
> прогона (`UserInteractionLevel.DONTDISPLAYALERTS`). Файлы открываются и
> закрываются **без сохранения** — оригиналы не меняются.

## `scripts/diagnostics/InspectCutCandidates.jsx`

Точечная диагностика **одного** проблемного файла, когда `PreflightBatch`
нашёл подозрительно мало контуров реза (например, 48 открытых линий вместо
~135 стикеров). `StickerExporter` ищет рез только по *обводке* — а дилайн
может быть задан заливкой, лежать в подслоях или быть незамкнутыми линиями.

### Что показывает (по активному документу)

- Классификацию всех путей: замкнутые / открытые / с обводкой /
  замкнутые-с-заливкой / **замкнутые только с заливкой** (главный кандидат в
  «рез заливкой»).
- Группировку замкнутых путей по цвету **заливки** — если есть цвет с
  количеством ≈ числу стикеров, значит рез задан заливкой, а не обводкой.
- Группировку обводок по цвету (как их видит экспортёр).
- Состав первых 8 групп верхнего уровня — из чего собран один стикер.
- Сколько путей лежит в подслоях (блайндспот экспортёра).

### Запуск

1. Открыть проблемный `.ai` в Illustrator.
2. `File → Scripts → Other Script…` → выбрать `scripts/diagnostics/InspectCutCandidates.jsx`.
3. Отчёт `<имя>__inspect.txt` ляжет рядом с файлом — переслать в чат.

## `scripts/fixes/FixClipCut.jsx`

Чинит макеты, где контур реза задан **невидимым clipping-путём** группы
стикера (без обводки и заливки) — `StickerExporter` такой рез не видит.
Приводит файл к общей конвенции: навешивает на контур видимую обводку
отдельным spot-цветом `CutContour`.

### Что делает (по активному документу)

1. Создаёт (или находит) spot-цвет **`CutContour`** — отдельный, чтобы группа
   реза в экспортёре была чистой и не смешивалась с посторонними линиями.
2. Проходит по верхнеуровневым группам видимых незаблокированных слоёв.
3. В каждой группе находит контур-обводку стикера: clipping-путь обрезанной
   группы, иначе — самый крупный замкнутый путь без заливки и без обводки.
4. Навешивает на него обводку `CutContour` (0.25 pt). Видимая графика стикера
   не меняется.
5. Сохраняет **копию** `<имя>__cut.ai` рядом. Оригинал на диске не трогается.

### Запуск

1. Открыть проблемный `.ai` в Illustrator.
2. `File → Scripts → Other Script…` → выбрать `scripts/fixes/FixClipCut.jsx`.
3. Открыть полученный `<имя>__cut.ai`, запустить `StickerExporter` и выбрать
   контур реза = **Spot "CutContour"**.

## `scripts/fixes/CloseOpenCutPaths.jsx`

Замыкает **открытые** контуры реза (с микрощелью), из-за которых стикер
обрезается с рваным краем. Делает то же, что ручной `Ctrl+J` («Join») в
Illustrator, но автоматически и по всему файлу — ручная работа в редакторе не
нужна.

### Что делает (по активному документу)

1. Собирает обводки, группирует по цвету, показывает диалог: какой цвет —
   контур реза (по умолчанию самый массовый), с указанием числа открытых.
2. Замыкает все открытые пути выбранного цвета (`path.closed = true`).
3. Сохраняет **копию** `<имя>__closed.ai` рядом. Оригинал не трогается.

### Запуск

1. Открыть `.ai` в Illustrator (актуально для `NAKL_JDM_300`, `NAKL_KOTY_PRODUKTY`).
2. `File → Scripts → Other Script…` → выбрать `scripts/fixes/CloseOpenCutPaths.jsx`.
3. Экспортировать стикеры уже из `<имя>__closed.ai`.
